# 00-workflow.md

## 作業開始時

- `docs/PROJECT_STATE.md` と `docs/NEXT_ACTIONS.md` を読み、現在地と次にやることを確認する。
- `git status` を確認し、未コミットの変更やブランチの状態を把握する。

## 変更の進め方

- 大きな変更・高リスクな変更: 調査 → 計画 → 実装 → 検証 → 記録（`docs/DECISIONS.md`）の順で進める。
- 小さく明確な変更: 過剰に計画せず直接修正する。
- 無関係な変更を1つのコミット・1つの作業に混ぜない。

## 完了報告の形式

- 何を変更したか
- 何を検証したか（実行できなかった場合はその理由）
- 未完了・保留にした点
- 次にやるべきこと（`docs/NEXT_ACTIONS.md` に反映する）
