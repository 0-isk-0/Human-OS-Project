# 対話アルゴリズム v0（インタビュー手順書ドラフト）

ステータス: ドラフト。Phase 1でいしこに実際に適用して改訂する。

## 目的

1回45〜60分程度のセッションを繰り返し、`personality-model-v0.md` のスキーマに沿った項目を抽出・確認・更新する。

## 全体ルール（すべてのセッション共通）

- **誘導しない**: 質問者（AI）の仮説を質問に混ぜない。クリーンランゲージの原則（本人の言葉だけを質問に埋め込む）を使う。
- **事実と推測を分離**: AIが抽出した項目は必ず `unconfirmed` として本人に見せ、「そうだ／違う／半分そう」の確認を取ってから `confirmed` にする。
- **記録**: セッションの発言ログにIDを振り、モデル項目の `evidence` から参照できるようにする。
- **1セッション1フォーカス**: 4領域を1回で埋めようとしない。

## セッション構成

### 0. チェックイン（毎回・5分）

- 「今日の調子はどう？」から入り、conditions領域のデータを毎回1件は自然に取る
- 前回のopen_questionsから1つを今日のフォーカスに選ぶ

### 1. 素材出し（10分）

フォーカス領域に応じて「要素」を出してもらう。

- values/thinking_patterns: 最近の具体的なエピソード3つ（迷った決断・熱中したこと・嫌だったこと等）
- goals: 今やっていること・やりたいと思っていることを列挙
- conditions: 最近調子が良かった日・悪かった日

抽象論ではなく**具体的な出来事**を素材にする（レパートリーグリッドの「要素」に相当）。

### 2. 掘り下げ（20〜30分）— 手法の使い分け

| 状況 | 手法 | 問いの型 |
|---|---|---|
| 要素が3つ以上ある | レパートリーグリッド | 「この2つは似ていて、これだけ違う。何が違う？」→ 本人固有の評価軸を抽出 |
| 大事なこと・好き嫌いが出た | ラダリング | 「それはなぜ重要？」を、終端（これ以上遡れない価値）まで反復。ただし尋問にならないよう言い換える |
| 比喩・イメージが出た | クリーンランゲージ | 「その『◯◯』は、どんな『◯◯』？」「その『◯◯』は他に何かある？」 |
| やりたいこと・行動の話になった | GROW | 目標→現状→選択肢→意思の順で具体化。goals領域の3層（vision/goal/project）に対応づける |
| 矛盾・両価性が見えた | 動機づけ面接 | 矛盾を指摘せず、両面をそのまま要約して返す（「一方では…、他方では…」）。どちらを取るかは本人が言うまで待つ |

### 3. 抽出と確認（10分）

- セッション中の発言から、スキーマに沿った項目候補をAIが提示（`unconfirmed`）
- 本人が1件ずつ「そうだ／違う／半分そう」で判定。「半分そう」は本人の言葉で修正してもらう
- **この確認体験こそがプロダクトの核**（「これは自分だ」感）。雑にしない

### 4. クローズ（5分）

- 今日更新された項目の要約
- 新しく生まれたopen_questions
- 次回のフォーカス候補

## セッション計画（Phase 1 = 最初の4回の想定）

1. 第1回: conditions＋素材集め（負荷が軽く、即効性を感じやすい領域から）
2. 第2回: values（エピソードからラダリング）
3. 第3回: thinking_patterns（レパートリーグリッド中心）
4. 第4回: goals（GROW中心）＋ モデルv0全体を「自分の説明書」として通読・判定

第4回終了時に「これは自分だ」と感じられるかがPhase 1の完了判定。

## Phase 1 での実行方法

コードは書かず、Claude（Enterprise）のプロジェクト機能またはClaude Code上でこの手順書を読み込ませて実行する。ログとモデル（JSON/Markdown）は本リポジトリの `model/` 以下に保存する（`[要確認]` 私的データを公開リポジトリに置くかは要判断 → 置き場所はセッション開始前に決める）。
