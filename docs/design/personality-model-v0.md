# 人格モデル v0.2 スキーマ

ステータス: ドラフト（v0.2）。原点レポート（ローカル保管・非公開）の8層構造と、初版の4領域を統合した。Phase 0でいしこ自身のモデルを作りながら改訂する。

## 設計原則

1. **すべては仮説である**: モデル内の記述は「診断結果」ではなく、確信度つきの仮説。本人が最終判定権を持つ。
2. **証拠リンク必須**: すべての仮説は、由来となった発言・出来事（事実ログのID）に紐づく。AIの推測と本人の発言を混同しない。
3. **本人判定**: 各仮説は `unconfirmed`（AI提示のみ）→ `confirmed` / `partial`（一部合う・本人の言葉で修正）/ `rejected` の状態を持つ。confirmedとpartialのみがモデルを名乗れる。
4. **反証も記録する**: 仮説に合わない発言・矛盾を隠さず `counter_evidence` に残し、条件差（いつ合って、いつ合わないか）を確かめる材料にする。
5. **履歴化**: 上書きせず更新履歴として残す。「以前はこう説明されていたが、こう変わった」を本人が見られる。
6. **状態と特性の分離**: 比較的安定した特性と、現在の状態・環境による反応を区別して保存する。
7. **二重表現**: 内部＝構造化データ（JSON）、外部＝物語的な「自分の説明書」（Markdown、生成物）。
8. **ポータブル**: 特定のLLM・サービスに依存しない形式。いつでも持ち出せる。

## 全体構造: 記録の仕組み（3層）× 内容の領域（6ドメイン）

### 記録の仕組み

| 層 | 何を保存するか |
|---|---|
| **事実ログ** | 本人が実際に述べた発言・出来事・選択。IDを振り、すべての仮説の根拠元になる |
| **仮説** | 事実群を説明する暫定モデル。必ず1つのドメインに属し、確信度・状態・証拠・反証を持つ |
| **更新履歴** | 仮説の修正記録（いつ・何が・なぜ変わったか） |

### 内容の領域（仮説の分類先）

| ドメイン | 記録する内容 | 例（内容は個人データのため非公開、形式のみ） |
|---|---|---|
| **reactions（反応）** | 瞬間的な感情・身体反応。最終判断とは分けて記録する | 「◯◯されると、まず△△と感じる」 |
| **processing（処理）** | 感情の後に行う思考手順・意思決定の順序 | 「感情→内省→仮説化→外部確認→統合」 |
| **values（価値）** | 何を良い・重要と判断するか。衝突時のトレードオフ | 「AとBが衝突したらAを取る」 |
| **relations（関係）** | 信頼・愛情・距離の条件 | 「◯◯という行動を信頼の証拠と感じる」 |
| **environment（環境）** | 能力が出る条件・消耗する条件・コンディションのパターン | 「◯◇が揃うと伸びる/△△で消耗する」 |
| **goals（目標）** | やりたいことの構造。vision→goal→projectの3層と、上位（価値）への接続 | 「この活動は◯◯という価値につながる」 |

初版4領域との対応: 価値観→values、思考のクセ→processing（＋reactions）、コンディション→environment（＋reactions）、目標→goals。原点レポートの8層との対応: 事実層→事実ログ、仮説層・更新履歴層→記録の仕組み、反応/処理/価値/関係/環境層→ドメイン（goalsは8層になかったため追加）。

## 仮説のスキーマ

```json
{
  "id": "hyp-001",
  "domain": "values | reactions | processing | relations | environment | goals",
  "statement": "仮説の一文（可能な限り本人の言葉を使う）",
  "confidence": "high | medium | low",
  "status": "unconfirmed | confirmed | partial | rejected",
  "restatement": "statusがpartialのとき、本人自身の言い直し",
  "evidence": ["log-2026-08-01-023"],
  "counter_evidence": ["log-..."],
  "conditions": "適用される状況 / されない状況（分かっていれば）",
  "recorded_at": "2026-08-01",
  "history": [
    {"date": "2026-08-01", "change": "何がどう変わったか", "reason": "本人の指摘・新しい事実"}
  ]
}
```

## 付属構造

### open_questions — モデルの空白・矛盾

AIがまだ分かっていないこと、仮説同士の矛盾。次回セッションの問いの供給源。

### insights — 一般化可能な発見（HOS Insight）

本人のケースから抽出した、**他者にも検証可能な一般仮説**。個人データを含まない形に抽象化して記録する（例:「瞬間反応と最終判断を分けないと人格モデルを誤る」）。これはHuman OSのサービス設計そのものへの入力になる。

```json
{
  "id": "HOS-001",
  "statement": "一般化された仮説",
  "source_case": "どのケース・セッションから生まれたか",
  "verified_on": []
}
```

### narrative — 自分の説明書（外部表現）

構造化データから生成する物語的なMarkdown。正本はJSON側。

## データの置き場所

本人の事実ログ・仮説（個人データ）は公開リポジトリに置かず、ローカル（`.local/model/`、Git管理外）に保存する。リポジトリにはスキーマ・手順・一般化されたinsights（個人特定情報を除去したもの）のみを置く。

## 参考にした足場（メモ）

- 8層構造と仮説検証サイクルは原点レポート（成立経緯レポート、ローカル保管）に基づく

- Big Five的な数値スコアはv0では持たない（本人の言葉＋証拠を優先。v1で再検討）
