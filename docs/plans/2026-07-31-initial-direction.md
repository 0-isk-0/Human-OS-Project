## 1. 結論: 「AIを作るのかMBTIを作るのか」は二者択一ではない

調査③の結論をそのまま採用する。**ナビ（AI）は内部に地図（人格モデル）を必要とし、地図は対話（構造化インタビュー）から作られる。** 3つは択一ではなくレイヤーである。

| いしこが挙げた成果物 | レイヤー | 中身 |
|---|---|---|
| 人格モデルの設計図 | 表現レイヤー | その人の価値観・思考のクセ・目標構造・コンディションパターンを保持するデータ構造 |
| 対話アルゴリズム | 取得レイヤー | 人格モデルを対話から引き出し・更新し続ける構造化インタビュー手順 |
| サービス仕様書 | ループレイヤー | 上記2つを包み、「モデルが本人に返って行動が変わる」までのループを回すアプリ |

## 2. 調査からの主要な根拠

### 空白地帯（= Human OSの勝ち筋）

- **「本人が読めて・直せて・持ち運べる明示的な人格モデル」を中核にした製品は存在しない**（調査①）。既存のユーザーモデルはブラックボックス（ChatGPTメモリ）か事実の羅列（Replika）。
- **「一回きりの診断」（MBTI系）と「診断構造を持たないコンパニオン」（Replika/Pi系）の中間、「対話で更新され続ける人格モデル」は未開拓**（調査①③）。
- 既存PKMは「情報」のOSであり、**「なぜ自分はこれを先送りするのか」「半年前の自分と何が変わったか」を扱うツールは事実上ない**（調査②）。
- 「覚えてくれるAI」単体はChatGPTに吸収されて死んだ（Rewind→Meta買収で終了、Dot終了、Pi→Microsoft）。**記憶レイヤーではなく「自己理解・判断支援」レイヤーで差別化する**（調査①）。

### 科学的な足場

- 内部表現には検証済みの連続次元を使う: **Big Five**（性格・最も再現性が高い）＋ **Schwartz価値円環**（価値観・82カ国で検証）。MBTIは妥当性が低い（5週間で39〜76%がタイプ変動）が、**「物語的なラベル」としてのインターフェース価値は本物**——16Personalitiesは「中身Big Five・ガワMBTI」で10億回受検を達成。→ **内部=連続値、外部=物語ラベル、の二重化**。
- 対話アルゴリズムの素材は数十年の実務史がある形式化された手法から合成できる:
  - **レパートリーグリッド法**（本人固有の評価軸を抽出。「AとBは似ていてCと違う点は？」）
  - **ラダリング**（「なぜそれが重要？」の反復で価値まで掘る）
  - **クリーンランゲージ**（質問者のバイアスを混入させない定型質問。LLMプロンプトと相性が良い）
  - **GROW / 動機づけ面接**（行動レイヤーへの接続）
- **Stanford 2024**: 2時間の構造化インタビュー記録をLLMに与えたエージェントが、本人の回答を正規化精度85%で再現。**人口統計やペルソナ記述より「インタビュー記録」が個人を捉える最良のデータ**。→ Human OSの中核資産は「良質な構造化インタビューのログ＋そこから抽出した構造」。

### 先行者からの教訓

- Kin（概念グラフ＋時間妥当性つき記憶）が思想的に最も近い先行者。「埋め込み＋RAGだけでは人のモデルは作れない」と明言している。
- Replika/Friendの教訓: 「感情的依存」を作る方向はエンタメとしては強いが、規制・倫理リスクを直接引き受ける。Human OSは**依存ではなく自己理解**に軸足を置く。
- PKMの教訓: 人はノートを再訪しない。**再訪を人間の意志に依存させた時点で負け**。ユーザーは「語るだけ」、構造化は機械が担う。

## 3. ヒアリングで確認できたこと（2026-07-31、2ラウンド）

- 対象: 自分専用に閉じず、**他人も使える前提＋研究成果としての完成度**を重視
- 痛み: ①頭が散らかって動けない ②自分を言語化できない ③判断で迷う ④記録が活きない——**全部**
- 直感: **「自分を理解してくれる相棒（AI寄り）」にワクワクする**
- 人格モデルに入れたいもの: **価値観・判断基準 / 思考のクセ / 目標構造 / 感情・コンディションパターン**（全部）
- データ: クラウド保存でよい（利便性優先）
- 過去の挫折: **ChatGPTとの壁打ち**（その場は整理されるが蓄積されない・毎回説明し直し）
- 形（UI）: 調査結果を見てClaudeが提案 → 本ドキュメント§5で提案
- ヒアリング自体を製品の核にするか: 未定 → §4のコンセプトでは核に置く提案

## 4. プロダクトコンセプト案

> **対話するほど育つ、自分が所有する「自分の説明書」。**
> AIが構造化インタビューでいしこを掘り下げ、その内容が「人格モデル」として目に見える形で蓄積・更新される。モデルは本人が読めて、直せて、持ち出せる。次の対話はモデルを前提に始まるから、毎回説明し直す必要がない。

- ChatGPT壁打ちの挫折（蓄積されない）への直接の解答になっている
- 「診断結果」という成果物が出るのでMBTI的な面白さ・共有可能性があり、他人にも試してもらえる
- 更新され続けるので一回きりの診断で終わらない
- 対話ログ＋人格モデルという成果物は、助成の研究発表とも相性が良い

## 5. 形の提案: レスポンシブWebアプリ

- **チャット画面**（AIインタビュアーとの対話）＋**モデル画面**（育っていく人格モデルの可視化）の2画面構成が最小形
- 他人に試してもらう・成果発表でデモする、の両方に最も向く
- スタックは既知のもので固める提案: 静的フロント＋serverless functions＋Supabase（開発者が他案件で実証済みの構成）＋Claude API
- `[要確認]` 制約: **助成はClaude EnterpriseシートでありAPIキーは既定では発行されない**（進捗と正当な理由を示せば問い合わせ可能）。→ §6のフェーズ順序はこの制約を前提に設計

## 6. フェーズ計画

### Phase 1: 対話アルゴリズムv0と人格モデルv0（コードなし・Claude Enterprise内で完結）

- レパートリーグリッド／ラダリング／クリーンランゲージ等を合成した**インタビュー手順書v0**を設計する
- それを**いしこ自身に実際に適用**し（Claude上でのセッション）、出てきた内容から**人格モデルv0のスキーマ**（JSON/Markdown）を設計・実装なしで作る
- 完了条件: いしこの人格モデルv0が1つ完成し、「これは自分だ」と本人が感じられること（＝コンセプトの最小検証）
- 副産物: この実績がAPIキー申請の「進捗と正当な理由」になる

### Phase 2: Webアプリ MVP

- チャット＋モデル可視化のWebアプリを実装（APIキー取得後。取得できない場合の代替も検討: 自費APIキー等 `[要確認]`）
- 完了条件: いしこがブラウザだけでPhase 1と同等のインタビュー→モデル更新を回せること

### Phase 3: 判断支援と他者展開

- 育ったモデルを使った判断支援（「いしこの価値観だとこの選択は…」）
- 他人に試してもらえるオンボーディング
- 成果発表用のまとめ
