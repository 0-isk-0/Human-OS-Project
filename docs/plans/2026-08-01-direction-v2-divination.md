# Human OS Project 方針 v2 — 「占い×AIの最強版」

作成日: 2026-08-01
ステータス: **却下（2026-08-01）。方針v3で置き換える。**

> **却下の理由**: 「占いとAIの最強版」という開発者の言葉を、Claude が「占いの体験設計（物語・周期・許可・アーキタイプ）を借りる」方向に解釈したが、開発者の意図と異なっていた。実際に求められていたのは、**選択肢で気軽に答えられる形式で、生育環境と生活史から「なぜ今こうなったのか」を根拠つきで説明するもの**であり、分析の比重（領域・深さ・時期・踏み込み度）をユーザー自身が選べること。占い的な演出は求められていない。
>
> **ただし本ドキュメントの一部は方針v3でも有効**: バーナム判定4基準、禁止構文の一覧、「これは違う」を一級のインタラクションにする設計、依存対策、Finn の Level 1/2/3 による提示順序、`[理想] or [影]` 命名、Golden Mean 3列、軌道の4つ組。これらは根拠づけと提示の技法であり、占いの枠組みとは独立に使える。
>
> 市場調査（§2）も参考情報として有効。
根拠: 市場・文献調査6本（第1次3本＝パーソナルAI/PKM/人格モデル文献、第2次3本＝占い市場/占いの心理メカニズム/リーディング提示技法）＋ 開発者ヒアリング3ラウンド ＋ 原点レポート（ローカル保管）

## 0. 一行で言うと

> **あなたが言ったことだけを根拠にした占い。**

占いの体験（物語・名前・周期・許可・関係）をすべて備えながら、一行ごとに「いつ、あなたがこう言ったから」という出典がついている。そして対話のたびに更新され、「これは違う」と言えば書き換わる。

## 1. なぜ「占い」なのか — 調査が示した構造

### 1-1. 占いの「当たってる感」は4つの技術で作られている（＝全部フェイク）

Forer(1948) 以降の実証研究で確立された、バーナム効果の増幅条件:

| 技術 | 内容 |
|---|---|
| **好意性** | 肯定的な記述ほど受容される |
| **個人化の演出** | 「あなたのために作成された」と思わせる |
| **高ベースレート** | 誰にでも当てはまることを言う（＝ユニークでないことが受容の条件） |
| **権威づけ** | 「NASA のデータ」「心理学に基づく」等 |

Forer の実験では、**全員に同一の13項目**を「あなた個人の結果」として渡し、的中度評価は5点満点で **4.30**。典型的な構文は「**時には**外向的、**時には**内向的」（両価接続＋緩い時間量化子＝反証不可能）。

**Human OS はこの4つを一つも使わない。**

### 1-2. 占いが本当に効いているときの仕組みは、別の5つ（＝全部借りる）

| 仕組み | 根拠 |
|---|---|
| **外在化** | 投影法研究（タロット=Semetsky 2006）。内側のものを外に置くと扱えるようになる |
| **内省の足場** | 立ち止まって考える構造そのものに価値がある |
| **許可を与える** | オープンラベル・プラセボ研究。**欺瞞は必要条件ではない**。主観的アウトカムに有効 |
| **物語の構築** | McAdams の narrative identity。贖罪的な語りはウェルビーイングと正の相関 |
| **自己検証** | Swann の自己検証理論。人は「既に知っていたことの言語化」を求める |

The Pattern 自身が公式に認めている: 「理想的には、あなたが自分について発見することは、**すでに知っているが、まだ受け入れたり信じたりしていなかったこと**を反映する」。

### 1-3. 分離を実現する唯一の手段＝出典の明示

```
✗ 「あなたには、まだ活かしきれていない力があります」    ← 検証不能・誰にでも当てはまる
✓ 「11月に『3日考えてから決める』と話し、2月にも同じ手順を説明しています」 ← 反証可能・出典あり
```

**バーナム文の判定4基準**（実装可能なフィルタとして採用する）:
1. **反証可能性**: この記述が外れている人を具体的に想像できるか
2. **ベースレート**: 何%の人に当てはまるか。70%超ならバーナム
3. **反転**: 反対のことを言っても「当たってる」と感じられるならバーナム
4. **出典**: 本人の引用可能な発言が存在するか

**この4基準を通らない文はプロダクトから出力しない。**

### 1-4. 構造的な優位

Co-Star も The Pattern も、日次リーディングの実体は **LLM生成ではなく「人力で書いた短文ライブラリ × 生年月日による条件分岐」** だった。Co-Star 公式も「NASA のデータを、AIと協働する人間の占星術師が解釈している」と明記している。

つまり**占いの体験設計は、極めて薄い根拠の上に成立している**。Human OS は同じ体験設計を、本人の実際の発言という圧倒的に厚い根拠の上に構築できる。

## 2. 市場の現実（数字）

### 2-1. 規模

- 日本の**占いサービス市場は 997億円**（矢野経済研究所 2023年度）。よく言われる「1兆円」は物販・ヨガ・宗教を含む広義の数字であり、**役務としての占いはその約1/10**。TAM 議論に1兆円を使わない。
- 6区分のうち**唯一「Web占い（アプリ・SNS）」だけが横ばい**。伸びているのは電話・チャットなど「人間と対話する占い」。

### 2-2. 二極化した利用者

```
Z世代      : 週1以上利用 33.9% ・ 課金ほぼゼロ
30-50代女性 : 金額の約90% ・ 相談の85%が恋愛
```

### 2-3. 追い風の数字（ザッパラス調査 2026年6月, n=1,020）

- **占いで知りたいことの1位は「自分自身」70.5%**（恋愛は20.0%）
- 信頼度は「**参考程度**」61.9%、「信じる」は合計30.7% → **当てにいく必要がない層が主流**
- ただし **AI占い経験率は20代男性56.4%・女性53.4%** → **「AI占い」はもう差別化にならない**

### 2-4. 実証済みの失敗

ザッパラス（占いコンテンツ最大手）は売上ピーク比 **-63.5%**、営業利益 **-90.2%**。ガラケー公式の月額300円という強制導線が消えた瞬間に崩壊した。
→ **「AIが毎日診断文を配るサブスク」は日本で一度実証的に失敗している。**

## 3. 解くべき3つの構造的問題

### 3-1. 共有可能性のパラドックス（最重要）

日本の診断利用シーンは **95.4%が「友人との会話」**。診断結果はシェアされるのではなく**交換される**。

```
「INFP」            → 突き合わせられる → 会話になる → 広まる
「あなただけの分析文」  → 突き合わせられない → 会話にならない → 広まらない
```

AIが完全パーソナライズできる2026年に、1ヶ月で100万人を集めたのは**64タイプ診断＝ラベルの細分化**だった。**Human OS の最大の強み（固有のモデル）が、そのまま最大の拡散上の弱点になる。**

**解: 二層構造。** ただし交換用の記号を「固定タイプ」にすると、開発者が最も嫌う「雑に理解されること」そのものになる。したがって**記号はタイプではなく「いまの局面」にする**（§4-1）。

### 3-2. 緩衝材の喪失

占いには「外れてるかも」という逃げ場がある。**証拠に基づくほどこの緩衝材を失う。** 日本MBTI協会には「このタイプは自殺しやすいと書かれて不眠症になった」レベルの被害相談が届いている。Co-Star の辛辣さは英語圏で機能したもので、**日本語で本人の実際の発言を根拠に断定すると、逃げ場がない分だけ破壊力が大きい。**

**解**: 影の指摘は必ず①駆動力とセットにし（`or` 構文）、②期限をつけ（局面として扱う）、③「これは違う」で即座に撤回できるようにする。

### 3-3. 依存リスク

Human OS は「記憶を持つ・情動的にミラーリングする・自己像を定義する」という**AI依存設計の三要素をすべて備えている**。意図せずして最も依存を生みやすいアーキテクチャになっている。

**解**: §6 の依存対策を設計段階から入れる。緩和策なしにこの構造は解決しない。

## 4. 中核設計

### 4-1. 情報アーキテクチャ: 最上位に「二軸」を置く

The Pattern から移植する最重要構造。**色を2つ決めて全画面で守る。**

| 軸 | 内容 | 語彙 | 更新頻度 |
|---|---|---|---|
| **傾向（永続）** | 何度も現れる型 | 「あなたは〜する人だ」 | ゆっくり |
| **局面（一時）** | 期限つきのフェーズ | 「いま起きていること」＋開始日・終了日・残り・ピーク | 週〜月 |

- **数値の強度スコアは出さない**（The Pattern は意図的に出していない）。強度は持続期間・ピーク窓・名前の感情的レジスターで伝える。
- **証拠ベースだからこそ、期間を実データで出せる**。占星術は天体で期間を決めるが、Human OS は「あなたが実際にこの状態を報告し始めた日」から出せる。ここで占いを追い越す。
- **共有される記号は「局面」の名前**にする。固定タイプではないので決めつけにならず、しかも交換可能（§3-1の解）。

### 4-2. 命名文法: `[理想] or [影]`

The Pattern の命名文法を、本人の言葉から抽出した駆動力に適用する。

```
「完璧主義 or 停止」
「探究心 or 散漫」
「面倒見の良さ or 自己消耗」
```

同一の駆動力の良い発現と悪い発現を同時に名指すため、**必ず半分は当たり、かつ追従（flattery）に見えない**。

VIA の Golden Mean 3列（過少 / 最適 / 過剰）と組み合わせる:

```
使えていない: 何も決められない
最適:        必要なところだけ徹底する
使いすぎ:     終わったものを終わらせられない
    └ 証拠: 「11月、提出済みの資料を4回開き直している」
```

**「過剰使用の指摘」は、証拠がなければ嫌味だが、証拠があれば洞察になる。占い・診断が構造的にできない領域。**

### 4-3. 「型」ではなく「軌道」を出力する

出力を単一ラベルにしない。最低限これを揃える:

```
(現在の型, いまの高さ, 調子がいい時に向かう先, 疲れた時に崩れる先)
```

- エニアグラムの統合/分裂の矢印と、Riso-Hudson の発達レベルから。**型を1点でなく4つ組にした瞬間、箱ではなく矢印になる。**
- 「高さ」は3段階で十分。
- 可視化は **Bullet Graph**（現在値の棒＋比較マーカー＋3段階の背景濃淡）。レーダーチャート批判（軸順の並べ替えだけで形が変わる、面積は無意味）を一切受けない。
- 「**リスペック**」概念（RPG由来）で枠づける: 診断は固定の型ではなく「**現在のビルド**。振り直せるが、コストがかかる」。決定論を避けつつ変化への動機を作る。

### 4-4. 読み物の順序（Finn の Level 1/2/3 × Spotify Wrapped）

治療的アセスメントの知見: **Level 1（本人が明らかに同意する所見）を先に出すと、Level 2/3（自覚の外の指摘）への受容度が上がる。**

| # | 役割 | 内容 |
|---|---|---|
| 1 | 入口の数字 | 反論不能な総量（「あなたは今年◯◯語を話した」） |
| 2 | **Level 1** | 本人が確実に同意する事実を1〜2枚 →「うん、そう」で信頼を建てる |
| 3 | 意外だが検証可能 | 気づいていなかったパターン。**必ず根拠の発言を併記** |
| 4 | 時間軸 | 年初と年末の差 |
| 5 | **Level 2/3（影）** | `or` 構文で名詞化。期限つき |
| 6 | 関係の中の自分 | 「◯◯な人といるとき最も◯◯」 |
| 7 | 発明ラベル（クライマックス） | ここだけが共有の主対象 |
| 8 | 締めの一文＋共有カード | 短い断定。9:16、共有摩擦ゼロ |

**Spotify Wrapped 2024 の炎上が最大の教訓**: 検証可能な事実カード（Top Genres / Top Albums）を削ってAI生成のもっともらしいラベルに置き換えた結果、「リーチは過去最大だが、最も多くのネガティブフィードバックを受けた」（同社幹部）。**ユーザーが愛着を持っていたのは「正確に言い当てられた」感覚だった。**

### 4-5. 「これは違う」を一級のインタラクションにする

**占いに構造的にできない、最大の差別化。**

外部権威（星）はコピーライターに3つの免罪符を与えていた。証拠が本人の言葉になると全部失われるので、代替を用意する:

| 失うもの | 代替 |
|---|---|
| 断定の許可 | 断定の主語を本人の発話に返す。「あなたは X だ」→「**3か月で11回、X と書いている**」 |
| 否定の受容 | 影の指摘は必ず駆動力とセット（`or` 構文）＋期限つき |
| 外れたときの逃げ道 | **反証可能性を弱点でなく機能に変える。**「これは違う」がモデルを更新する |

これは Open Learner Model 研究の **negotiable / editable user model** そのもの。The Pattern が批判された「ブラックボックス問題」（推論を一切開示しない）を構造的に解決する。

**位置づけ: 「当たる占い」ではなく「あなたが訂正できる鏡」。**

### 4-6. 空状態を最初に書く

**何も言うことがない日に無理やり何か言うと、全体の信頼が壊れる。**

```
「今週は、あなたについて新しく言えることが見つかりませんでした。
 これは正常です。何も起きていない時期は誰にでもあります。」
```

### 4-7. 生成方式: ライブラリ × 証拠スロット

Co-Star も The Pattern も、毎回LLM生成ではない。The Pattern は「ChatGPT や他社AIは使っていない。数千の人間が書いたインサイトに基づく」と明示している。**声の一貫性と品質安定はここから来ている。**

**Human OS も「フレーズ・ライブラリ × 証拠スロット」構成を採る。** LLM の役割は次に限定する:
1. 発言からの証拠抽出・要約
2. ライブラリからの選択
3. 対話的な深掘り（インタビュー本体）

注意: The Pattern はコンテンツ枯渇による同一メッセージ再送で批判された。**ライブラリ規模がボトルネックになる。**

### 4-8. コピーの実装ルール

| ルール | 出所 |
|---|---|
| 通知は1文・短く・ヘッジなし。説明はタップ先 | Co-Star |
| 命令／断定／疑問をローテーション | Co-Star |
| 専門用語（心理学・統計）を全面排除。「回避傾向スコア0.72」でなく「近づかれると引く」 | The Pattern が占星術用語を書かないのと同じ理由 |
| 弱みには必ずアクション要求をセットで付ける | Personal user manual の実践 |
| **攻撃的トーンの配合比は2〜3割まで**（Co-Star の実測比率。ミームの印象に合わせると自己効力感を毀損） | VICE の "ambient anxiety" 批判 |
| 分類しつつ分類を否定する免責文を必ず1つ入れる | Gallup / VIA の確立パターン |
| **断定の直後に必ず証拠を1つ添える** | 星の権威の代替 |

**禁止 ↔ 推奨（文言レベル）**

| ✗ | ✓ |
|---|---|
| 「あなたには、まだ活かしきれていない力があります」 | （出力しない） |
| 「慎重ですが、大胆になれるときもあります」 | 「11月にこう話し、2月にも同じ手順を説明しています」 |
| 「あなたは慎重な人です」 | 「決めるまでに時間をかけることが多い、というパターンが3回の記録に出ています」 |
| 「今日は休んでください」 | 「過去2回、同じ密度の週のあとに体調を崩したと話しています。今回も同じ形です」 |
| 「AIが分析した結果、あなたは…」 | 「あなたが話したことを整理すると、…」 |

## 6. 倫理境界と依存対策

### 6-1. 絶対に避けるもの

1. **出典のない断定** — hot reading（事前入手した情報をその場で読み取ったふりをする詐術）と構造的に同型
2. **rainbow ruse 構文**（「◯◯だが、時には△△」）
3. **Jacques statement**（年齢・ライフステージの一般論を個人洞察として出す）
4. **vanishing negative** — 「違う」と言われたとき、より広い記述に逃げる。**「違う」はモデルの更新イベントとして扱い、言い換えで吸収しない**
5. **固定タイプ名の付与** — 固定マインドセット＋ステレオタイプ化を誘発
6. **好意性による受容の稼ぎ** — それはまさにバーナム効果の利用
7. **「MBTI」を名乗ること** — 日本MBTI協会が公式に注意喚起。独自体系を作る
8. **評価・選抜への転用** — 就活でMBTIを使った学生の54.5%が回答を偽装した。評価に使われると認識された瞬間、入力品質が崩壊する

### 6-2. 依存対策（設計に明示的に入れる）

- **意味生成をユーザーに残す**: 完成した自己記述を渡し切らない。「これをどう読むか」を本人に返す
- **多義性の保持**: 同じ証拠から複数の読みを提示できるようにする（arXiv:2602.11367 の「意味の平板化」批判への対応）
- **利用頻度の設計**: 毎日引ける占いアプリの形式は依存設計そのもの。週次を基本とする
- **「AIが見抜いた」という帰属を作らない**: 帰属先は常にユーザー自身の発言
- **オフランプ**: 「この問いは人間に相談したほうがよい」を判定して返す
- **メンタルヘルス責任を後回しにしない**: The Pattern は AI会話機能投入の9ヶ月後に自傷ポリシーを新設した。自己理解 × 対話型AI × 本人の実際の発言は、占星術アプリより深く踏み込む

### 6-3. 中核原則

- AIは診断者ではなく、仮説を作る共同研究者である
- 本人の言葉が、AIの一般論より優先される
- 仮説は訂正・削除・保留できる
- 人間の価値を点数化しない
- 「理解できないこと」を欠陥とせず、不確実性として残す
- 成果は的中率ではなく、**本人の納得・行動・自己理解の改善**で測る
- 枠づけは「これがあなたです」ではなく「**これは現時点のあなたの一つの読み方です**」

## 7. 研究としての価値 — まだ誰も答えていない問い

調査の結果、**次の問いに既存研究の答えが存在しない**ことが分かった。

> **出典つきの人格記述は、出典なしの記述より「当たっている」と感じられるのか、それとも感じられなくなるのか。**

理論上は両方ありうる:
- **上がる説**: 自己検証理論。長期・反復・本人の言葉ベースの関係では、一致性が好意性に勝る
- **下がる説**: バーナム効果の除去。「誰にでも当てはまること」を削ると、的中感を作っていた主要因が消える

**これは A/B テストで測定できる、本プロジェクトの中心的な実証課題である。** 助成プログラムの研究成果として、これ以上ないテーマ。Phase 1（友人テスト）をそのまま実験デザインにする。

派生する検証課題:
- 「証拠つきの許可」は、超自然的な許可と同等の行動効果を持つか（オープンラベル・プラセボからの類推は成り立つが、直接検証はない）
- 物語形式の自己記述は、特性リスト形式より固定マインドセットを誘発しにくいか

## 8. フェーズ計画 v3

### Phase 0: 本人ケーススタディ ＋ リーディング試作（コード不要）

- 原点レポートの暫定モデルを1件ずつ検証（第1回セッション）
- セッションを重ね、傾向／局面・`or` 構文・軌道の4つ組を実データで埋める
- **手書きで「リーディング」を1本作る**（§4-4 の順序で。出典つき）
- 完了条件: 本人が読んで「これは自分だ」と感じ、かつ**バーナム判定4基準を全行が通過している**

### Phase 1: 友人ミニテスト ＝ そのまま実証実験（コード不要、1〜2人）

- 同じ人に**出典あり版／出典なし版**の2種のリーディングを作り、的中感・納得感・行動変化を比較する
- 副次: 同意手順、所要時間、誤推定パターン、日本語での影の指摘の受容度
- 完了条件: §7 の中心的問いに対する予備的な答えが出ている

### Phase 2: Webアプリ MVP

- 対話（インタビュー）／モデル（傾向・局面）／リーディング の3画面
- 「これは違う」ボタンを一級市民として実装
- フレーズ・ライブラリ × 証拠スロット構成
- 前提: Claude APIキー（Phase 0〜1 の実績を添えて申請）

### Phase 3: 関係機能と拡大検証

- **2人のモデルを突き合わせる機能**（Co-Star と The Pattern が独立に到達した最良の課金対象。日本の診断文化＝交換とも一致）。占いの相性診断が推測でやっていることを、**証拠つきで**できる
- 友人3〜5人 → 10〜20人へ拡大
- 成果発表用まとめ

## 9. 名前について

プロジェクト名「Human OS」は研究名として維持し、**プロダクト名は別に付ける**ことを推奨する。方向性の候補:

- **鏡の系統** — 「訂正できる鏡」というポジションを直接表す
- **言葉の系統** — 「あなたの言葉だけが根拠」を表す
- **局面の系統** — 二軸設計の「いまどこにいるか」を表す

「MBTI」「診断」「AI占い」を名前に入れない（商標・差別化の両面で不利）。
